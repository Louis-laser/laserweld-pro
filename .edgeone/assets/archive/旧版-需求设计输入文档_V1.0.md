## 1. 项目概述

### 1.1 项目背景

激光焊接工艺参数查询系统，旨在为激光焊接从业人员（工艺工程师、操作员、研发人员）提供一个快速、准确的工艺参数检索工具。通过输入材料、厚度、接头类型等条件，一键获取推荐的焊接参数（功率、速度、离焦量、保护气等），减少试错成本，提升工艺开发效率。

### 1.2 项目目标

| 目标 | 说明 |
|------|------|
| **短期目标** | 搭建一套可用的Web版焊接参数查询系统，支持多条件检索 |
| **中期目标** | 建立标准化的参数录入/导入流程，支持Excel批量导入 |
| **长期目标** | 成为激光焊接行业的工艺参数参考标准，支持数据贡献与共享 |

### 1.3 项目范围

**本次范围（V1.0）：**
- Web端参数查询界面（PC + 移动端适配）
- 多条件检索（材料、厚度范围、接头类型）
- SQLite本地数据库存储
- Excel批量导入工具
- 30+条种子参数覆盖常用材料组合

**不在本次范围：**
- 用户权限管理（登录/注册）
- 多人协作编辑
- 工艺参数自动计算/推荐算法
- 移动端App（原生）
- 在线数据同步

### 1.4 用户画像

| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| 工艺工程师 | 需要快速查参数、做对比 | 精确检索+参数对比 |
| 焊接操作员 | 现场使用，移动端为主 | 简单快速查询 |
| 工艺研发 | 需要积累和整理数据 | 数据导入导出 |
| 初学者 | 需要参数参考和引导 | 浏览+推荐 |

## 2. 系统架构

### 2.1 技术栈（V1.0）

| 层级 | 技术选型 | 版本 | 说明 |
|------|----------|------|------|
| **后端框架** | FastAPI | ≥0.100 | Python异步Web框架 |
| **数据库** | SQLite | 内置 | 轻量级，零配置，单文件 |
| **前端** | 原生HTML+CSS+JS | — | SPA单页应用，无框架依赖 |
| **导入工具** | Python + openpyxl | ≥3.0 | Excel文件读取 |
| **运行环境** | Python | ≥3.9 | CPython |
| **服务器** | uvicorn | ≥0.20 | ASGI服务器 |

### 2.2 系统分层

```
┌─────────────────────────────────┐
│          Web浏览器               │  ← 用户访问端
├─────────────────────────────────┤
│       HTML + CSS + JS           │  ← 前端层（SPA）
│   (嵌入式，由FastAPI返回)         │
├─────────────────────────────────┤
│   FastAPI RESTful API 接口       │  ← API层
│   /api/search                   │
│   /api/materials                │
│   /api/joint-types              │
├─────────────────────────────────┤
│          SQLite 数据库           │  ← 数据层
│      weld_params.db             │
├─────────────────────────────────┤
│     Excel导入工具                │  ← 运维工具
│     import_excel.py             │
└─────────────────────────────────┘
```

### 2.3 数据流

```
用户查询流程：
输入条件 → Fetch GET /api/search → SQLite查询 → JSON返回 → 渲染结果卡片

数据导入流程：
编辑Excel → python3 import_excel.py → 写入SQLite → 重启服务生效
```

## 4. 数据规格

### 4.1 数据库表结构（wall_params）

这是系统的 **核心数据模型**，任何迭代不得破坏向下兼容性。如需新增字段，必须遵循后文「字段变更规范」。

```sql
CREATE TABLE weld_params (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增主键
    material1     TEXT NOT NULL,         -- 材料1（母材1）
    material2     TEXT NOT NULL,         -- 材料2（母材2，同种材料时等于material1）
    thickness     REAL NOT NULL,         -- 板厚 (mm)
    joint_type    TEXT NOT NULL,         -- 接头类型（对接焊/搭接焊/角接焊等）
    speed         REAL NOT NULL,         -- 焊接速度 (m/min)
    power         INTEGER NOT NULL,      -- 激光功率 (W)
    defocus       TEXT DEFAULT '',       -- 离焦量 (mm)，用字符串支持"+3"/"-1"等符号格式
    shield_gas    TEXT DEFAULT '',       -- 保护气体（如"氩气(Ar)"）
    gas_flow      REAL DEFAULT 0,        -- 气体流量 (L/min)
    fixture       TEXT DEFAULT '',       -- 工装夹具形式
    quality       TEXT DEFAULT '',       -- 质量等级（Ⅰ级/Ⅱ级/Ⅲ级）
    note          TEXT DEFAULT '',       -- 备注/注意事项
    is_premium    INTEGER DEFAULT 0,     -- 是否为高级参数(0=通用,1=高级)
    image_url     TEXT DEFAULT '',       -- 焊缝截面图/实物图URL
    video_url     TEXT DEFAULT '',       -- 焊接过程视频URL
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP  -- 记录创建时间
);
```

### 4.2 字段定义规范

| 字段名 | 数据类型 | 约束 | 填写规范 |
|--------|----------|------|----------|
| material1 | TEXT | NOT NULL | 写全称+牌号，如"不锈钢304""碳钢Q235" |
| material2 | TEXT | NOT NULL | 同种材料时与material1相同，异种时分别填写 |
| thickness | REAL | NOT NULL, >0 | 单位mm，精确到0.5mm |
| joint_type | TEXT | NOT NULL | 标准接头类型名称，不包含特殊字符 |
| speed | REAL | NOT NULL, >0 | 单位m/min，精确到0.1 |
| power | INTEGER | NOT NULL, >0 | 单位W，整数 |
| defocus | TEXT | 允许空 | 格式：符号+数字，如"+1""-2""0" |
| shield_gas | TEXT | 允许空 | 格式："气体名(化学式)"，如"氩气(Ar)" |
| gas_flow | REAL | 允许0 | 单位L/min，无保护气填0 |
| fixture | TEXT | 允许空 | 如"气动夹具""手动夹具""铜制工装" |
| quality | TEXT | 允许空 | 仅填Ⅰ级/Ⅱ级/Ⅲ级，大写罗马数字 |
| note | TEXT | 允许空 | 简明扼要，控制50字以内 |
| is_premium | INTEGER | 0或1 | 仅特殊工艺参数标记为1，常规参数标记为0 |
| image_url | TEXT | 允许空 | 完整URL，或留空 |
| video_url | TEXT | 允许空 | 完整URL，或留空 |

### 4.3 字段变更规范（重要）

> 此规范保证不同版本的迭代之间，数据库和API接口的兼容性。

**新增字段：**
1. 必须为 `TEXT` / `INTEGER` / `REAL` 类型（禁止复杂类型）
2. 必须设置 `DEFAULT` 值
3. 必须同时更新：数据库schema、API响应模型、前端渲染逻辑、导入工具
4. 新增字段的 `key` 命名使用 `snake_case`

**修改/重命名字段：**
- ❌ 禁止，应新增字段 + 废弃旧字段

**废弃字段：**
- 保留在表中不动，前端API停止返回
- 在数据库schema中加注释 `-- DEPRECATED: 废弃于YYYY-MM-DD`

## 5. 接口规范

### 5.1 API 端点一览

| 方法 | 路径 | 说明 | 当前状态 |
|------|------|------|----------|
| GET | `/api/search` | 参数查询（核心接口） | ✅ 已实现 |
| GET | `/api/materials` | 获取材料列表 | ✅ 已实现 |
| GET | `/api/joint-types` | 获取接头类型列表 | ✅ 已实现 |
| GET | `/` | 返回前端页面（SPA） | ✅ 已实现 |

### 5.2 接口详细定义

#### GET /api/search

**请求参数：**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| material | string | ❌ | "" | 材料关键词，模糊匹配material1和material2 |
| thickness_min | float | ❌ | null | 最小板厚(mm) |
| thickness_max | float | ❌ | null | 最大板厚(mm) |
| joint_type | string | ❌ | "" | 接头类型，精确模糊匹配 |
| page | int | ❌ | 1 | 页码，≥1 |
| page_size | int | ❌ | 20 | 每页条数，≤100 |

**响应体：**

```json
{
  "total": 5,
  "results": [
    {
      "id": 1,
      "material1": "不锈钢304",
      "material2": "不锈钢304",
      "thickness": 1.0,
      "joint_type": "对接焊",
      "speed": 1.3,
      "power": 1800,
      "defocus": "+1",
      "shield_gas": "氩气(Ar)",
      "gas_flow": 15,
      "fixture": "气动夹具",
      "quality": "Ⅰ级",
      "note": "标准参数，适用范围广",
      "is_premium": 0,
      "image_url": "",
      "video_url": ""
    }
  ]
}
```

**排序规则：** 按功率升序 `ORDER BY power`

#### GET /api/materials

**响应体：**

```json
{
  "materials": ["不锈钢304", "不锈钢316L", "碳钢Q235", ...]
}
```

#### GET /api/joint-types

**响应体：**

```json
{
  "joint_types": ["对接焊", "搭接焊", "角接焊"]
}
```

### 5.3 API 设计原则

1. ✅ RESTful风格，使用HTTP动词表达操作
2. ✅ 统一错误返回格式（后续迭代完善）
3. ✅ 默认启用CORS（开发阶段`allow_origins=["*"]`）
4. ✅ 分页参数标准化（page/page_size）
5. ⏳ 全量接口增加 `version` 字段（下个迭代）

### 5.4 后续迭代准备（不破坏现有接口）

- 如需增加新查询维度 → 新增 query parameter，不要修改现有参数语义
- 如需增加新返回字段 → 在 `results[]` 的每个对象中新增 key，不删除现有 key
- 如需改版 → 路径前加版本号 `/api/v2/search`

## 9. 迭代与变更规范

### 9.1 文档定位

本文档是 **项目设计输入的唯一权威来源**（Single Source of Truth）。

- 所有开发、测试、验收以本文档为准
- 所有迭代修改首先更新本文档，再更新代码
- 本文档与代码不一致时，以 **最新的文档版本** 为准

### 9.2 版本号规则

```
V{大版本}.{小版本}
```

| 版本 | 说明 |
|------|------|
| V1.0 | 初版，基础查询+导入 |
| V1.x | 功能增补，不破坏向后兼容 |
| V2.0 | 架构变更或破坏性更新 |

### 9.3 变更流程

```
变更请求 → CEO审核 → 更新本文档(V+1) → 更新代码 → 单元测试 → 归档
```

1. **提出变更** — 描述变更内容、原因、影响范围
2. **CEO审核** — 判断变更是否合理，是否与项目目标一致
3. **更新文档** — 在本文档对应章节修改，在「版本变更记录」中登记
4. **更新代码** — 按照文档规范实现
5. **归档** — 旧版本文档保留在 `docs/archive/` 目录

### 9.4 禁止行为

| 行为 | 后果 |
|------|------|
| 不更新文档直接改代码 | ❌ 不得通过，必须退回 |
| 修改字段定义却不更新schema | ❌ 数据不一致，需回滚 |
| 删除/重命名已有API参数 | ❌ 破坏前端兼容性 |
| 在代码中硬编码业务逻辑却不文档化 | ❌ 需补充文档 |
